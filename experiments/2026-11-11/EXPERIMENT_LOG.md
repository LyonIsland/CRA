# 实验过程与失败记录

本记录描述可观察的配置变化、实验结果和工程修正。完整逐次结果在 [CSV](run-ledger.csv) 和 [JSON](run-ledger.json)，原始日志、动作轨迹、评价数据和图像由仓库证据与 Release 全量归档共同保留。

## 阶段一：旧协议与新协议分开

此前工程实现了单块抓放、彩色零件搜索、概念搭建与人机协作流程。旧流程包含颜色身份、运动学、场景标定或接触连接近似。
它们仍属于项目历史，但不能作为“仅单台 RGB、无场景捷径”的实现或成功率证据。
全量历史日志（包括 75 个大型 XR JSONL 文件）在 `xr-history` 归档中；旧版结果、图片与权重在 `project-outputs` 中。

新协议隔离控制器输入：一台腕部 RGB、任务说明图像（需要时）和自身指令记忆。环境初始化和独立评价可以使用场景数据，但不得回传给控制策略选择动作。
所有散件使用统一灰度材质，取消颜色与实例身份的对应。初始化后不改写物体位姿，不启用积木抓取固定约束。

## 阶段二：BRICKLAB 说明书平台整合

将用户提供的 BRICKLAB 本地源码接入 Windows 平台，支持网页模型、Studio/LDraw 输入、三类说明书和页面图像生成。
同一作品进入持续机械臂工作区，提供对应散件、说明书、腕部相机及手动示范采集。缺少正式说明书策略权重时，自动搭建按钮与后端均拒绝执行。
场景联通、手动单步动作和示范保存通过检查，均不等于完整搭建成功。
上游源码没有 Git 元数据，因此仅记录原 ZIP/源码树 SHA-256，不虚构来源 commit；实际安装的源码快照随 `simulation-assets` 归档提供。

## 阶段三：夜间视觉/动作预训练

先进行了 CPU/CUDA、运动预测及平衡损失等小规模试验，记录保存在 `evidence/camera_training/pilot*` 及对应日志中。
随后运行独立 CUDA 环境中的 96 轮真实交互采集与增量预训练。监督器限制总时长、子进程时间与磁盘余量，保留每轮候选权重、验证报告、学习率选择及最终留出测试。
图像预测与逆动作误差优于简单对照，但没有完整装配示范，因此没有把这些权重自动部署为搭建策略。

## 阶段四：从基本功能开始实现抓取

选择无需深度输入的无标定视觉伺服基线：灰度轮廓获取矩形目标、光流跟踪、空夹爪图像定位、小幅关节试探、图像雅可比与阻尼最小二乘控制。
使用腕部正负旋转的图像导数增加轴线对准约束；闭爪后反向执行自身接近命令抬升并保持。

开发中遇到的主要问题与处理：

| 可观察问题 | 采取的修正 | 证据与限制 |
|---|---|---|
| 积木与夹爪投影阴影连成一个轮廓 | 增加多尺度局部灰度对比；避免将分离区域闭合粘连 | 保留真实相机回归样例与失败末帧 |
| 侧面或夹爪被当成完整目标 | 几何尺寸、矩形度及跟踪一致性过滤 | 仍有初始获取失败，未声称通用检测 |
| 反复重新选光流角点导致目标漂移到阴影 | 保留同一组物体表面特征点，进行前后向光流与 RANSAC 检查 | 修正后出现新场景成功，但重复运行仍可能丢失 |
| 探测关节命令达到限位，反向动作不再抵消 | 调整固定观察姿态，并在执行器发现限幅时停止 | 使用自身命令积分，不向控制器提供编码器读数 |
| 大幅方向调整、闭爪或开爪造成自遮挡 | 检查不同夹爪状态及试验主动观察 | 固定扫描与额外预对准没有稳定解决问题，未保留为最终算法 |
| 视觉上接近目标不能证明抓住 | 采用独立位置和双侧接触评价 | 评价不触发策略重试或提前选择动作 |

`dev-1` 没有完整结果文件。`dev-3/4/6/7/19` 保留了 STOP 标记，属于开发中主动中断，不是完成的成功尝试。
部分早期运行没有源码快照或详细错误字段，只保留其实际存在的证据，不补造不可恢复的中间版本。
`dev-11` 在开发种子 41001 首次真实抬升约 69.5 mm，并保持双指接触 3.44 秒。

之后的 `validation-51001`、`validation-51001-v2/v3` 及 `dev-12` 至 `dev-20` 对种子 51001 进行了调试。
虽然目录名称含 `validation`，**51001 已用于调参，因此这些运行全部按开发记录处理，不进入独立成功率**。
最终 `dev-20` 成功抬升约 70.1 mm、保持 3.66 秒。试验过程中失败、未完成和成功记录全部保留。

## 阶段五：冻结版本与新场景测试

冻结控制器、执行器与环境源码后，预先指定五个新种子 52001–52005，逐场景运行，不修改代码、不替换失败样本。
结果为三个成功、两个初始目标获取失败。冻结源码快照在 [frozen-source](frozen-source/)；每次策略快照、哈希、动作轨迹和独立评价在 [frozen-eval-v1](evidence/camera_grasp/frozen-eval-v1/)。
当前 60% 仅表示这五个入门场景的观察结果，不能作为稳定通用抓取能力的声明。

## 阶段六：失败的在线负对照与有效机械对照

在线张爪测试在目标跟踪阶段失败，未进入夹取，所以不能用其失败证明闭爪作用。
随后把一个成功运行的全部动作分别做正常回放与张爪回放。原始回放重新成功，张爪回放未抬升、未形成持续双指接触。
两组机械臂指令逐项相同，只有指定阶段的夹爪动作不同；源码和动作哈希、原始计划与比较结果均保留。
该结果只用于物理机制检查，不混入在线视觉控制的成功率。

## 验证与尚未完成的部分

已完成的工程检查包括单 RGB 输入合同、颜色通道置换不变性、动作限幅与守恒、真实阴影/夹爪图像回归、训练分组与数据隔离、报告路径边界及 BRICKLAB 平台联通。
浏览器检查确认说明书到场景、手动动作、记录示范和缺失策略拒绝行为；抓取报告的五条测试记录、视频播放、实时状态与机械对照展示通过检查。

仍需补充：遮挡下主动观察与可靠重新获取、更大规模留出测试、同形多件与堆叠、材质和光照变化、放置与插接、说明书条件策略，以及真实硬件验证。
任何后续算法改动应另开版本与测试批次，不能把当前失败样本反复调到成功后改写本批次分母。
